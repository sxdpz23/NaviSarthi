## Vehicle-specific console support

0.5.0 adds Meteor 350 first in setup and Settings, using black surfaces and rose
accents. Meteor exclusively selects Tripper Pod BLE screens, permissions, settings
and navigation. Himalayan 450, Guerrilla 450, Bear 650 and Himalayan 750 exclusively
retain Tripper Dash Wi-Fi functionality and their existing themes.

Saving a different vehicle stops navigation, voice and the old connection before
enabling the next owner. The planned itinerary and independently saved Pod/Dash
pairing and settings survive. The console back stack is recreated; old callbacks
and pending writes are invalidated.

Pod implementation includes discovery/service validation, six-digit PIN authorization,
reverse GATT replies, serialized/checksummed packets, bounded reconnect, two-arrow
guidance, metric distance/ETA modes, clock/day/night settings, headless GPS/voice
and ride recording. See docs/tripper-pod.md for evidence and hardware limitations.
Unverified alerts/progressive fill and firmware updates are excluded.

Kotlin namespace/source packages: `com.sxdpz23.navisarthi`. Installed application
ID remains `com.navisarthi.app` for update compatibility. Version 0.5.0, code 29.
APK packaging/publication remains separate from implementation.

Validation (2026-11-11): Kotlin compilation, Android test source compilation and
all 114 JVM tests passed, with zero failures/errors/skips. Generated BuildConfig
and merged manifest confirm namespace com.sxdpz23.navisarthi, application ID
com.navisarthi.app, version 0.5.0/code 29. Source inspection found no remaining

Checks used an ignored Gradle init script and isolated output directory because

installed or published. Physical Pod/Dash qualification requires the bikes;
Android tests were compiled but not run on a device.

## Offline navigation options

- Fixed-route download is the current option. Download a planned itinerary with its route legs and turn instructions, then follow it offline.
- Regional download is a future option alongside fixed routes. Download an area first, then choose destinations and calculate or reroute multi-stop journeys offline inside its coverage. Validate the map package, local routing, and motorcycle access before release.
